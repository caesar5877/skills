# 画面放置与联想质量校验（含排障）★用户重点

## R｜来源与依据

原书 P035（联想四要素）、P037–P038（串连三原则）、P048–P049（画面必须落在地点上、图像清晰度、
蜈蚣-和尚错例）、P070（玩具化/模型化）、P124（跨材料污染）。

原文的否定式规定（P048–P049）：

> “有的人将两个词语联系在一起了，却没有跟地点紧密结合；有的人将其中一个词语跟地点联系得很紧密，
> 发生的动态画面却不在地点上。”

作者给的错例：桩是树根，画面是“树根上面飞出一条蜈蚣咬到了一个和尚”——他判定这是错的，
因为“蜈蚣咬和尚这一动态的瞬间并不是发生在树根上的”，下次回忆到树根时“会出现想象空白”。
清晰度要求同样具体：只想象出一个“长方形的东西”不够，会与其他长方形编码混在一起（P049）。

## I｜这条能力在说什么

地点桩是索引，画面才是内容本身。这一步的质量决定宫殿到底有没有用。

三条正向增强（四要素）：**看得见的画面、物件之间的动作、允许夸张不可能、调用多种感官**（声音/颜色/气味/味道/触觉）。
串连时另加三条硬规则：图像要具体到某个物（“仪器”不行，要具体到显微镜）、相邻两项必须**接触式**相连
（“小猫爱苹果”“小猫旁边有苹果”都不算）、**用动词**连接，最好正在进行。

三条否定式（“三不”）：不得只把两个项目串在一起而脱离地点；不得让动态发生在别处；不得似是而非。

排障部分最有价值：回忆失败不是一个笼统的“我没记住”，而是五种可区分的技术故障——

| 症状 | 原因 | 处置 |
|---|---|---|
| 到某桩一片空白 | 动作没落在这个桩上 | 重写画面，让动作的主客体包含该桩 |
| 想起一类东西但不确定是哪个 | 编码不具体 | 补颜色、图案、边角、品牌等互斥细节 |
| 顺序错乱、放错桩 | 桩同质 / 遍历方向不定 | 换有特征桩，固定顺逆时针（转 palace-building） |
| 两道题内容互相串 | 载体不独占 | 分码段或另建桩组 |
| 记得画面却想不起条目 | 画面与目标词关系太松 | 用动词把目标词本身放进画面 |

## A1｜原书案例（作者错例与例题，非本卡合成）

- **蜈蚣与和尚（错例）**：见 R 段，作者用来说明“动态必须发生在地点上”，并给出正确改写方向：
  蜈蚣咬住树根、或树根旁的和尚（P049）。
- **模糊编码（错例）**：只想到“一个长方形的东西”→ 与其他长方形编码互相混淆（P049）。
- **玩具化（例题）**：牌面编码是“骑士”“山鹿”，地点是一张小桌子；“一头山鹿把一个工人狠狠地顶到了音响上”，
  尺寸对不上时“将编码玩具化、模型化”（P070）。
- **标准例题**：40 位数字第一组 9203 → 92 足球、03 凳子，“一个足球飞到树根下面，掉在了树根那里的凳子上面”
  （P065–P067）——动作、地点、方向都在同一处，是合格画面的模板。

## A2｜我的适用表述

**用户处在这些情境**：

1. 桩建好了，放东西时“想到地点但想不起放了什么”。
2. 回忆时串位：把 A 的内容想到 B 上。
3. 自己造了画面，想让第三方判断行不行。
4. 编码/图像太模糊，猜不出来。
5. 用了宫殿但整体效率没提升，怀疑画面质量。

**语言信号**：“想到地点想不起东西”“画面不够清楚”“这样联想行吗”“记混了”“画面串了”“要夸张到什么程度”
“回忆出现空白” / “I see the location but not the item”“my image is blurry”“images get mixed up”。

**与相邻能力的区分**：

- `palace-building` 判桩合不合格；本卡判画面合不合格（用户抱怨“记不住”时常常是这里，而不是桩）。
- `abstraction-conversion` 解决“抽象词根本没法想象”，即**还没有画面**；本卡处理**已有画面但不好用**。
- `mnemonic-list` / `clause-loci` 是造完联想之后的组织方式。
- `self-check` 在“方法都对但仍失败”时做四维归因。

## E｜执行

**输入契约**：① 桩组（已按 palace-building 验收）；② 要放的项目序列；③（排障时）一次真实回忆的结果
——具体到哪一桩、看到什么、错成什么。缺 ③ 时先让用户做一次闭卷复述，不能凭猜测排障。

**放置流程**

1. 默认**每桩两个项目**，编成一个动态小片段（扑克两张牌、数字两组码、两个词条）。
2. 检查画面是否满足：**动作的施事或受事之一就是该桩本身**（树根夹住报销单，而不是树根旁边发生别的事）。
3. 检查细节：桩与项目各自有颜色/形状/边角，同类项目细节互斥。
4. 加动作与夸张（正在进行式动词优先），并至少调用两种感官。
5. 尺寸不匹配时把编码缩成玩具模型（不改变项目身份，只改尺度）。
6. **逐桩试述**：盖住项目表，只看桩号复述；错的那一桩回到步骤 2 重写。

**排障流程**（输入是一次失败）

1. 让用户描述“当时脑子里出现了什么”，先分类到上表五类之一（描述不出即判为画面不具体）。
2. 只改对应项，不要整套推倒。
3. 改后立即复测该桩；连续两次仍失败 → 换桩或换项目载体（数字码），并记录该桩不适合此类内容。

**输出契约**：

- 放置表：`桩号 | 项目 1 | 项目 2 | 画面（一句话，含桩本身的动作）`
- 排障表：`失败桩 | 症状 | 判定类型 | 改写后的画面 | 复测结果`

**完成标准**：盖住项目表，按桩号能复述全部项目；随机抽桩（含倒序）能说出该桩画面与所承载项目；
画面句子中出现桩名本身作为动作的参与者。达不到即判未完成，不得转“多背几遍”。

## B｜边界与不适用

- **没有合格载体时不要用本卡**：画面质量建立在桩之上，桩不合格（同质、无序）时再好的画面也会串位，先回
  `palace-building`。
- **夸张不是目的，也不必然更好**：作者无条件主张“越夸张越有效”，但**没有给出反例**。实践中夸张元素可能
  喧宾夺主（记住荒诞情节、忘了目标词）。因此判据始终是“能否由桩准确回忆出目标词”，不是画面多离谱。
- **原书未给的判定阈值**：多久想不起来算失败、一个画面最多改写几次，原书都没规定。本卡采用
  “两次改写仍失败就换载体”作为操作约定，须向用户说明这是约定而非作者结论。
- **中文母语的想象偏好**：夸张荒诞的画面依赖具体物名词；抽象度极高且无法具象的材料（法律构成要件、数学定义）
  更适合走 `mnemonic-list` 或 `clause-loci`，不要硬画。
- **不要用于纯理解型内容**（作者原书自设边界：纯记忆知识点 ≤30%）。
- **不做**：不承诺“过目不忘”；不在没有复测的情况下宣布画面已改好。

## 相关能力

关系类型：依赖（用本卡前须先懂它）/ 对比（按情境二选一）/ 组合（常配合使用）。
机器可读的补读清单见 Bundle 中本能力的 `also_read`。

- **依赖** `palace-building` — 没有合格桩（同质、无序）时，再好的画面也会串位，必须先修载体。
- **组合** `abstraction-conversion` — “根本想不出形象”属于转换问题，转换出对象后再回本卡落地。
- **组合** `self-check` — 正确性、备用性掉分通常落到本卡的五类画面故障。
- **对比** `mnemonic-list` — 不靠画面、靠“压成一句 + 还原测试”的材料走 mnemonic-list。
